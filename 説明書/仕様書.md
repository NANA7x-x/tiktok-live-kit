# TikTok LIVE オーバーレイ 仕様書（v4）

この仕様書だけで、同じシステムをゼロから再現できるように書いたもの。
v3（パチンコ風の抽選オーバーレイ）から、**運の要素と景品をなくした「確定型」**に作り直した版。

---

## 1. 方針（いちばん大事）

TikTok LIVE のルールで問題になりやすい「ギフトで運任せのゲームを回す」「ギフトと引き換えに景品を約束する」を避ける。

- **運の要素なし**：ギフトの「1個あたりのコイン数」で起きることが必ず決まる。抽選・スロット・ルーレット・確率は使わない
- **景品なし**：お返しは配信の中で配信者が演じるもの（語尾・一人称・声・手元カメラ・ピアノ・軽い運動）だけ。色紙・壁紙・手書きメッセージなど配信外で渡すものは採用しない
- **金額・ランキングを出さない**：画面・Discord・VRChat に金額（コイン数・円）と順位を出さない（本人用のファイル記録は除く）
- **ギフト以外でも進む**：みんなで達成ゲージは いいね・コメント・フォロー・シェアでも貯まる。ギフト1回で入る量には上限
- **うるさい連動音を鳴らさない**：音量上限＋コンプレッサー
- **配信者が演じる**：自動で完結するゲームにしない。画面は「今なにを演じているか」と「順番待ち」を見せるだけ
- 体を傷める罰（手・指・喉）、ゲームプレイを縛る罰は禁止（ピアニストのため）。軽い運動（スクワット10回）だけ可。回数を増やしたり罰ゲームっぽく見せたりしない

## 2. システム構成

```
TikTok LIVE
  └─ tiktok-live-connector（非公式ライブラリ）
       └─ app/server.js（ポート 21213）
            ├─ 正本の保持と保存（設定/kit_state.json）
            ├─ HTTP: overlay.html（/overlay.html /front.html /back.html /transparent.html）, remote.html
            ├─ WebSocket: state（全体の状態）と ev（演出のきっかけ）を全クライアントへ
            ├─ Discord Webhook（任意）
            └─ VRChat OSC チャットボックス（任意）
```

## 4. ギフト表（bands）

各段：`from`（何コインから）、`tier`（演出の大きさ S/M/L/XL）、`ico`、`fx`（起きること）、`short`（レール用の短い名前）、種類（その場で／変身：声・カメラ・ボイス＋`min`分／リクエスト）、`on`。

初期値：

| from | tier | 起きること | 種類 |
|---|---|---|---|
| 1 | S | お名前コール | その場で |
| 10 | M | 語尾「にゃん」 | 変身：声 3分 |
| 30 | M | 一人称「俺」固定 | 変身：声 5分 |
| 50 | M | ボイスエフェクト（ロボ声） | 変身：ボイス 2分 |
| 100 | L | スクワット10回 | その場で |
| 199 | L | 手元カメラON | 変身：カメラ 10分 |
| 500 | L | ピアノ サビだけ1曲 | リクエスト |
| 1,000 | XL | ピアノ フルで1曲 | リクエスト |
| 5,000 | XL | ピアノ弾き語り1曲 | リクエスト |

- 判定は「1個あたりのコイン数」以上で一番大きい `from` の段（ONの段だけ）
- 連投（repeatCount）は個数分：変身は時間×個数、リクエストは個数分（最大10）
- コイン数が取れないギフトは1コイン扱い

## 4.5 順番リスト・セリフ・早口言葉

- 段に `list`（順番リスト）があると、起きることの `{x}` に今の項目が入る。発動するたびに次の項目へ（K.idx に段ごとの位置）。ギフト表には「つぎ ○○」を出す
- 同じ段の別の項目が発動中にまた来たら、その場で次の項目に切り替えて時間を足す
- `use:'line'` … セリフ集（K.lines）から順番に1つ。画面に大きく出す
- `use:'challenge'` … 早口言葉（K.twisters）を順番に。チャレンジは1つずつ（順番待ちあり）。リモコンで ○ を3回で成功、× で失敗→罰ゲーム（K.penalties を順番に）。成功・失敗はハイライトに記録
- リスト類はリモコンで編集（1行1つ、最大100）

## 5. 変身スロット（slots）

- `voice`（語尾・一人称など）、`cam`（手元カメラ）、`vfx`（ボイスエフェクト）の3枠。枠どうしは同時に動く
- 同じ段が発動中なら**延長**。別の段なら枠内で**順番待ち**。終わったら自動で次へ
- 状態は `{cur:{bandId,user,fx,ico,short,end}, q:[...]}`。`end` はサーバー時刻。クライアントは serverNow との差で補正
- リモコンから「終了→つぎへ」「全部消す」

## 6. リクエスト（requests）

- ピアノ系の段とTEAM達成で `{id,user,kind,at}` が追加される
- 画面には「リクエスト◯件／つぎ：誰（種類）」。リモコンで「済」

## 7. みんなで達成ゲージ（team）

- 加算：いいね（増えた数×0.6）、コメント6、フォロー25（1配信1人1回）、シェア20（1人60秒に1回）、ギフト min(350, 8+√コイン×6)×個数(最大10)
- 満タン（初期1000）で 0 に戻り、`ev:team` 演出＋リクエストに「TEAM達成」
- 85%以上でゲージ点滅＋心音
- いいねは合計数（totalLikeCount）の増加分だけ数える（再送・再接続で二重にならない。配信ルームが変わったらリセット）

## 8. 画面

1080×1920。上端288px（TikTokの表示）と下672px（コメント欄）には何も置かない。

アバター中心モード：
- 上：配信内容ラベル（金文字・黒縁）、NOW（声の変身＋残り時間＋NEXT件数）、HEAT、CAM／VOICE／REQ の小プレート
- 左右レール：ギフト表。半分ずつ。4段以上は自動で縦スクロール。ギフトが来ると該当段が光る
- 中央下：トースト（小ギフト・フォロー・シェア。同じ人の連打は ×N にまとまる）、CHAIN、TEAMゲージ
- 中央はアバターのために空ける

ゲーム配信モード：上＝情報（縮小）＋ギフト表を横スクロール、真ん中＝ゲーム、下＝アバター。演出は上の段で出し、暗転はほぼなし。

## 9. 演出（すべて「見た目と音だけ」。結果は変えない）

- S：トースト＋短いチャイム（連打で音程が上がる）
- M：横から突き刺さるプレート
- L：上下の黒帯＋集中線＋キュイン音→重低音→斜めの帯に名前
- XL：約1.7秒の溜め（光の玉・鼓動・揺れ）→閃光・衝撃波・金の放射線・重低音
- TEAM達成：専用演出
- 大きい演出はキューで1つずつ。大量に来ても画面にたまらないように：同じ人の同じ段は×Nにまとめる／待ちが3件以上になったら中ギフト（M）を「まとめてありがとう」1枚（名前を最大6人＋ほか◯人）に／待ちが6件を超えたら古い大ギフト（L）もまとめに入れる（特大XLとTEAM達成は必ず単独）／待ちがあるほど1つを短く（待ち1〜2件で0.72倍、3件以上で0.5倍。特大の溜めも省略）
- 画面の粒（紙吹雪・星・ハート）は最大650個まで
- CHAIN：設定秒数（初期10秒）以内のギフトでつながる。リングの残り時間、1つごとに音程が上がる
- HEAT：盛り上がり（ギフト・いいね・コメント等で上がり、時間で下がる）。LV.0〜MAX。画面の縁だけ光る（全面の色は変えない）
- テスト送信の演出には「TEST」バッジ

## 9.4 ギフトのきらめき（すべてのモード。ギフトの絵文字は演出に使わない）

- 派手さ lv = log10(コイン×個数+1)×1.15（最大5。ドパドパは1.25倍）
- 花火：下から打ち上がって星形のきらめきに開く。lv に応じて 1／2／4／7／11 発。開く大きさも lv で大きく
- 画面いっぱいのキラキラ（瞬く星）：10＋lv²×14 個
- lv 2.2 以上：流れ星（lv×1.4本）＋ホログラムの光が画面をなでる
- lv 3.3 以上：上の方にうっすらオーロラ（約4秒）＋キラキラ追加
- 特大ギフトの中央は、ギフトの絵文字の代わりに回転する宝石形のきらめき
- 物理は時間基準（OBSが30fpsでも同じ速さ）

## 9.5 演出の強さ・パネルの見せ方（settings.fxLevel / settings.look）

- `look: panel`（しっかり）… 今までの板つき。`look: airy`（すっきり・アバター重視）… 左右レールの板をなくしてアイコン＋縁取り文字だけ、HEATの板を隠し、上の板を少し薄く（アバター中心モードのときだけ）
- `fxLevel: dopa`（ドパドパ）で追加されるもの（どれも結果は変えない）：
  - 中以上のギフトで画面が一瞬ズームする（パンチ）。L/XLでジャックポット音
  - CHAINが 5・10・15・20・30・50・75・100（以降50ごと）でカットイン
  - FEVER TIME：CHAIN 8以上 か HEAT LV.4以上の間、上のラベルが「🔥 FEVER TIME 🔥」になり、縁が128BPMで脈打ち、ビートが鳴る。画面全体の色は変えない

## 9.55 いいねのハート（settings.likeHearts）

- いいねが届くたび、画面の下（コメント欄の上）から左右の端寄りにハートがわいて、ゆらゆら上る（顔にかぶらないように）
- 数：ふつう 1＋いいね数/12（最大10）、ドパドパ 1＋いいね数/6（最大20）
- いいね 500 ごとに大きなハートがまとめてわく＋チャイム

## 9.6 ランキング（settings.rank / K.rank）

- その日の配信ぶん。新しい配信（ルームが変わる・切断後の再接続）で自動リセット。リモコンからもリセット可
- MVP：1個あたりのコイン数がいちばん大きいギフトをくれた人（同じなら先にくれた人）
- ギフトランキング：コイン合計の順（上位5人を表示）。`showCoins` が false（初期）のときは順位と名前だけ
- いいねランキング：いいねイベントごとの likeCount の合計
- 表示：右レール（ランキングON中はギフト表は左レールにまとめる）。6秒ごとにページをめくる。ゲーム配信モードでは上の段の右半分に横並び
- 注意：コイン数を画面に出すと、ギフトの催促や「点数を競うゲーム」と取られやすくなるため、初期はOFF

## 9.7 レイアウト編集（K.layout）

- 動かせるパーツ：topic・hud・legL・legR・rank・team・chain・toasts
- モード（avatar / game）ごとに `{dx, dy, s}` を保存し、CSS の translate と scale で反映（元の配置からのずれ）
- プレビュー（?preview=1）で編集モードにすると、各パーツに枠が出る。ドラッグで移動、右下の●で拡大縮小、ダブルクリックでそのパーツをリセット

## 10. ふんわりエフェクト（雰囲気レイヤー）

- 奥（back）：小さめのぼけた光の玉、虹色の光の筋、ゆっくり
- 手前（front）：大きく強くぼけた光の玉（近景＝被写界深度っぽさ）、角の光漏れ、きらめき、ビネット、下のもや
- 色は配色テーマから自動で作る。強さはリモコンで
- アバター自体のブルームや背景だけのぼかしは、オーバーレイではできない（VTube Studio の Visual Effects か、OBS の obs-shaderfilter（bloom）／Composite Blur で行う）

## 11. 見た目（style）

- 色：accent（メイン）、gold（金・強調）、cyan（ゲージ）、plate（板）、frame（枠）、ink（文字）。プリセット7種（neon/pastel/lavender/sakura/cyber/gold/mono）
- フォント：見出し・本文を選択（手書き系：油性マジック、はちまるポップ、よもぎ、クレー、Zen紅道 など）。PCのフォント名の直接指定も可。数字は Orbitron か見出しと同じ
- 枠：光る縁／線／二重線／なし。形：角カット／角丸。板の濃さ 30〜100%
- 大きな文字は単色＋太い黒縁取り（変形・装飾過多にしない）。板はベタ塗り

## 12. WebSocket

サーバー→全体：
- `state` … `{serverNow, settings, bands, style, team:{value,max,label}, slots, requests, conn:{auto,live,user}, vrc:{enabled}}`
- `ev` … `kind: gift | like | comment | follow | share | team`。gift は `{user, giftName, giftIco, coins, count, test, band:{id,tier,ico,fx,min,slot,req}, ext}`

クライアント→サーバー：
`hello`, `setSettings{settings}`, `setLayout{mode,id,dx,dy,s}`, `setLists{lines,twisters,penalties}`, `chMark{ok}`, `chSkip`, `chClear`, `resetLayout{mode,id?}`, `rankReset`, `setBands{bands}`, `resetBands`, `setStyle{style}`, `testGift{user,coins,giftName,count}`, `testEvent{kind,user}`, `slotEnd{slot}`, `slotClear{slot}`, `reqDone{id}`, `reqClear`, `teamSet{value}`, `connectMode{auto}`, `connectNow`, `vrcTest`

## 13. TikTok接続

- 自動：失敗が続くと 20秒→60秒→180秒間隔。配信中・切断直後10分は20秒。切断時は5秒後に再接続
- 手動：リモコンの「今すぐ接続」の時だけ
- 連投ギフトは確定したイベントだけを最終個数で処理。1個あたりのコイン数は `data.gift.diamondCount` ほか候補を総当たり

## 14. 連携

- Discord：配信開始告知（TikTok・YouTube）、終了時に「ありがとうリスト（名前だけ）」「ハイライト（経過時間つき）」「おつかれさまレポート（金額なし）」
- VRChat：チャットボックスに「🎁 ○○さんから『ギフト』 → 起きること」。金額なし。テスト送信は流さない。1.5秒間隔・重複抑制・144文字

## 15. 自動更新

- app/server.js が差し替わると、文法チェック後に自動再起動（KIT_RESTARTED=1 の後継はポート解放待ち）
- overlay.html は `/version` を20秒ごとに確認し、変わっていれば自動で読み直す。リモコンは自動では読み直さない（F5）
